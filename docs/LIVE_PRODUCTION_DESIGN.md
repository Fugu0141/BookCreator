## 1. 背景と製品原則

実機検証で独自部品の中央キャンバスが未計測のまま空欄になる問題が報告された。さらに、編集してから毎回ワンテンポ置かないと実物を確認できない制作体験全体への改善要望があった。#126で部品エディタの初期表示・編集時の自動計測を導入したが、個別の修正に留めず制作全体を見直す。

基本原則: 「編集すると、実際の仕上がりがその場で変化する」。制作中の確認は自動、通常保存・部品登録・出版は明示。確認のためだけに余計なボタンを押さない。表示は現在の未保存案を含む。手動更新は障害時の再試行や明示的な全冊検証などの補助に限定する。

リアルタイムは毎キー入力で全冊の同期組版を行うことではない。操作は即時、局所表示を優先、正しい組版は自動で追従。大規模書籍であっても入力を待たせず、処理中の旧結果と最新結果を明確に区別する。

| 対象 | 現行 | 変更する方針 |

| 執筆・原稿プレビュー | renderer.jsx の invalidate がプレビューDOMを削除、render が手動組版ボタンを起点とする。render 自身も invalidate を呼ぶ | 原稿選択時に表示、確認済み入力を自動組版。旧結果を維持し最新結果へ交換 |

| フォント・スタイル | 変更で組版を無効化。実際の紙面は別画面の組版で確認 | 同じ組版エンジンによるサンプルまたは現在の原稿を隣に常時表示。保存不要で反映 |
| 書籍設定 | 用紙・余白・原稿順等の変更後に組版が必要 | 用紙境界、余白、本文領域、改ページを設定画面で自動表示。未保存値で描画 |

| 部品カタログ | 簡易見本（参考表示） | 実際の部品定義とフォントによる計測済みサムネイル。表示範囲内を優先 |
| 数式 | mathDraft変更で数式プレビューを生成、無効時は空欄 | 現在の式を自動描画。無効時は前回結果とエラーを区別。本文内/独立数式の紙面反映も自動 |
| 図表・脚注・相互参照（既存/将来） | 挿入後の全体確認が必要な箇所、未実装機能あり | 追加開発の時点からライブ組版への接続を必須にする。番号や参照は全体文脈で解決 |
| 出版 | 試作組版・診断・正式出力未対応 | 自動診断と現在の組版状態を表示。正式出力は明示操作・最新の全冊検証が必須 |

## 3. UIの共通ルール

- 広い画面の執筆は左に原稿構成、中央に本文、右に実紙面を基本とする。紙面の非表示は任意。狭い画面は本文/紙面をワンタッチ切替し、紙面へ移動すれば自動表示。本文入力中に紙面へ強制移動しない。
- デザイン/書籍設定は主編集項目と現在の仕上がりを並べる。既存の画面分離を維持し、全機能を一画面へ詰め込まない。
- レイアウトは全冊を基本とし、選択原稿だけの確認も選べる。原稿単体と全冊の範囲は明示する。
- 原稿切替/書籍切替時は異なる書籍・対象の旧紙面を新しい対象として表示しない。初回表示中は理由付きの準備表示。
- 同一対象の更新時は直前の成功結果を残す。薄い表示と「更新中」または「前回の表示・エラー」を表示し、古い座標のクリック/ドラッグ/逆引きを無効化する。成功後は新しいDOMへ一度に交換。エラーは該当箇所に表示し、既存原稿を変えない。
- クリック・ドラッグ・色選択・寸法入力は画面へ即応する。選択中の要素、フォーカス、スクロール、倍率、見ているページを可能な限り維持。復旧候補の明示選択を勝手に確定しない。
- 実測確認/組版更新は必要な場合のみ補助ボタンにする。保存ボタンは保存としてのみ機能し、自動描画に伴うディスク書き込みはしない。登録/適用に最新の実測が必要なら自動実測完了で条件を満たす。

## 4. 表示と組版の責務

編集状態（原稿、編集中のテーマ、用紙設定、部品案）を唯一の入力とする。既存 Markdown/Core/LayoutEngine の解析・番号解決・実測・ページ分割を同じ経路で使用。プレビュー用の独自組版ルールや実物に似せた別レイアウトを増やさない。サンプルを使う場合はサンプルであることを明示し、実際の本文スタイル・部品コンパイル・物理寸法を使用する。

処理の流れ:

1. 編集を受け取り、作業案を即座に更新する。編集世代を進める。
2. 対象と表示範囲から不変の組版スナップショットを作る。書籍識別子、原稿IDとrevision、未保存原稿、テーマrevisionと未保存値、用紙・順序、素材・フォント、文脈を含む。
3. 共通スケジューラが短時間の変更をまとめ、表示中の対象を優先する。同一対象の古い要求は置換し、実行中の結果は世代と対象が一致した場合のみ採用する。
4. 実エンジンで検証、計測、組版。現在の表示を消さずに新しい表示を準備する。
5. 最新結果だけを表示し、ページ位置・選択・倍率を復元。エラー時は前回成功結果を旧版として保持し、逆引き/登録/出版を禁止する。
6. 通常保存・復旧記録・出版は別系統。現在の表示が自動更新されてもディスクには保存しない。

### 4.1 世代と競合

現行 renderer の generation は原稿操作（範囲選択・数式/参照編集・診断ジャンプ）の妥当性にも使われる。組版要求開始でこの世代を進めると、編集中の操作を誤って無効化するため、編集世代と描画要求IDを分離する。UIの状態変更と組版要求は別管理。古い組版結果を破棄する仕組みは必須。

現行 main の readBook は通常操作と共通 busy を使う。バックグラウンド描画の読取が保存や画面移動を妨げないよう、読取専用スナップショット経路を設けるか、安全な待機・再取得を設計する。書籍切替、外部編集、revision競合、素材変更時は結果の適用を拒否する。安全性を下げて非同期化しない。

### 4.2 更新状態

idle（対象なし）→ pending（変更・初回）→ rendering（実測中）→ ready（最新）または error（失敗）。旧結果の有無は状態と別に管理。ready は最新入力スナップショットと一致する場合に限る。保留中・実測中・エラーの旧結果を最新と表示しない。診断・逆引き・登録/適用・出版の有効性は状態から判断する。

### 4.3 更新間隔と優先度（暫定目標、実測で調整）

| 操作 | 方針 / 目標 |
|---|---|
| ドラッグ・選択・値入力 | 次の描画フレームを目標に入力・選択へ即応。ドラッグ中は局所座標を仮表示し、離した後に実測で確定 |
| 小規模部品・単一数式 | 初回自動表示、変更後80–180ms程度の合流待ち。不要な再計測を回避 |
| 選択原稿・設定の実紙面 | 入力確定後150–300ms程度で自動組版要求。通常の短い原稿で1秒以内の最新表示を目標 |
| 全冊 | 現在見ているページ/原稿を優先。全冊の完了を入力の条件にしない。後続段階で依存関係・キャッシュ・差分再組版 |
| IME | 変換中の入力を確定扱いしない。変換確定後に組版。選択・フォーカスを奪わない |

待ち時間は測定目標であり保証ではない。フォント/画像読込、大規模書籍、ページ分割が重い場合は進捗を示す。並列に無制限な組版を開始しない。まず正確なフル再組版＋要求合流を実装し、キャッシュは依存関係検査後に導入する。HTML/MathMLの実測が必要な処理を根拠なくWorkerへ移さない。解析など独立可能な処理のみ計測に基づき分離を検討。

## 6. 受入検査

- 初回: 原稿選択・部品エディタ起動・デザイン/書籍設定/レイアウトへの移動のみで対象の実物が表示される。
- 編集: 文字、数式、色、寸法、フォント、用紙、余白を変更し、手動更新せず最新の実測結果に追従。通常保存前のファイルハッシュ不変。
- 連続操作: A→B→Cを短時間で変更、A/Bの遅い結果を採用しない。編集欄・カーソル・ズーム・スクロールを維持。古い紙面をクリックして原稿が書き換わらない。
- エラー: 一時的な不正数式・不正寸法・リソース欠落・外部変更から正常値へ戻すと自動回復。旧結果が残る場合は明示し、古い結果で登録/出版不可。
- IME: 日本語入力、連続変換、取消、Enter確定、Ctrl+S、数式/参照編集中に描画要求で編集範囲を無効化しない。
- 保存/切替: 描画中でも通常保存・書籍切替・終了が安全。別書籍の結果を混ぜない。復旧領域、通常保存、明示登録を混同しない。強制終了検査を維持。
- 実機: 1280×720/1920×1080、100/125/150%のDPI、長文・図表/数式・複数部品。操作→表示までの時間を測り、体感と合わせて改善する。
- 全5CIに成功してからmainへ統合。実際のWindows版を配布し、利用者の再検証で制作体験を確認する。

## 7. 優先順位

リアルタイム制作設計の改修・実機検証を新機能より優先する。図表・脚注・出版の機能拡張は一旦保留し、追加する際には本仕様の自動表示を受入条件とする。実際の版の一致、操作の継続性、データの安全性を同時に満たす。画面を一括で全面書換えせず、各段階の配布物で検証する。
