# BookCreator システム境界・堅牢化方針

- 2026-11-26 / UX-10h-3c
- 利用者要望: 要所の責務を分離し、堅牢性を向上させる。
- 関連: LIVE_PRODUCTION_DESIGN.md
- 状態: 段階的な改修方針。将来の境界は実装済みを意味しない。

## 原則

- 分割単位は責務・データ所有権・障害境界・テスト可能性とする。ファイル数を目的にしない。
- UIはユーザー操作と表示、編集サービスは原稿案、組版サービスは不変の入力に対する結果、保存サービスは永続データを担当する。
- Markdownの解析・構文検査はBookCreator_Markdown、組版規則と計測はBookCreator_LayoutEngine、文書から組版入力への変換・参照解決は既存Core経路を使用する。UIに同等の組版規則を重複実装しない。
- モジュール境界の入出力と失敗条件を明示する。保存・登録・出版は明示操作とrevision検査を必須とし、プレビューを保存経路から分離する。
- 非同期結果は対象・世代・revisionの確認後のみ採用する。中断不能な処理が残っても古い結果を採用しない。
- IPCでは送信元・引数・書籍セッション・許可された操作を検証し、rendererに任意ファイルアクセス権を与えない。
- 外部プロセスやWorkerへの分離はCPU負荷・DOM依存性を計測して判断する。論理的な分離が即座に障害のプロセス隔離を意味するわけではない。

## 描画要求スケジューラの契約（UX-10h-3c）

- 1インスタンスにつき実行中1件、待機中最大1件。新しい要求は以前の待機要求を置換する。
- submitは要求IDを発行し、以前の結果を失効させる。invalidateは編集・対象変更時に待機要求を除去し、実行中の結果も失効させる。
- 呼出側はDOM変更・診断・遅延フォーカス・完了状態の反映直前にisCurrentを確認する。
- 実行中処理の物理的な中断を保証しない。失敗時も次の要求を実行できることを検査する。
- スケジューラはReact・IPC・ファイル・組版エンジンに依存しない。実際の描画結果はrenderer側で管理し、今後表示アダプタへ分離する。
- 今段階は手動描画の挙動を維持する。時間による合流、画面ごとの自動要求、旧紙面保持、再試行は未実装。

## 組版準備・紙面アダプタの契約（UX-10h-3d）

- `layout-input.mjs`: 入力検証、文脈判定、未保存原稿と保存済み原稿の合成、既存Coreによる組版オプション生成・フォント検証。React・DOM・IPCに依存しない。依存するエンジン関数は引数で渡す。診断は呼出側へ返す。
- `measured-paper.mjs`: 実測済みDOMからページ情報と逆引き範囲を組み立て、操作をコールバックに委譲する。原稿や保存状態を直接変更しない。
- rendererは要求の状態、組版用読取、エンジンの呼出、結果の採否、画面遷移を担当する。既存の世代検証を維持する。
- 既存挙動を維持する分離段階であり、完全な不変スナップショット、表示位置維持、旧紙面保持、自動組版は次段階で扱う。

## 紙面保持・交換の契約（UX-10h-3e）

- `paper-display.mjs` は前回成功ホストのみを所有する。書籍セッション・選択原稿・表示範囲が一致する場合に限り、旧ホストをinertにして保持する。対象が異なる場合は即時消去する。
- 最新世代の計測とメタデータ構築が完了した場合のみ新ホストと交換する。旧表示の逆引きは世代ゲートで拒否し、紙面状態がreadyでない場合は出版/ページ操作の最新結果として扱わない。
- 同一対象の交換時はスクロール座標を引き継ぎ、ページ数減少時はページ番号を範囲内に補正する。既存倍率制御を維持する。物理ページ内の厳密な位置復元は未検証。
- 旧紙面は失敗時にも保持できるが、初回エラーは旧紙面を生成しない。手動更新のままの段階で、自動組版は後続。

## 執筆ライブ組版（UX-10h-4a）

- `live-preview-delay.mjs` は200msの合流と取消のみを担当し、React・IPC・組版エンジンに依存しない。遅延要求は編集/画面変更で取り消し、既存の最新要求スケジューラへ委譲する。
- 執筆画面の自動組版は既定ON。広い画面は紙面を初期表示、狭い画面は紙面を開いたとき自動表示。非表示時は描画要求を出さない。手動更新・自動組版の明示OFFも残す。
- IME/構造編集作業中・保存/復旧処理中は新しい自動要求を出さない。自動組版は画面・フォーカス・保存状態を変更せず、結果の状態は紙面と診断へ反映する。失敗は次の編集または手動更新で再試行する。
- 実機性能、画像読取分離、競合後の自動再要求、全冊と設定の自動表示は後続。従来の手動操作検査を維持し、既定ONでの初回表示・IME・最新紙面・フォーカス・元ファイル不変の実GUI検査を別に追加する。

## 全冊ライブ組版と表示範囲（UX-10h-5a）

- `live-preview-policy.mjs` は自動組版の必要性と表示範囲を決定する純粋関数。タイマー、React、IPC、実測処理に依存しない。
- レイアウト画面の既定は全冊。原稿未選択でも組版可能。執筆画面の既定は選択原稿、紙面非表示時は自動要求を抑止する。
- 明示的な組版範囲の選択は同じ画面内で優先する。画面の通常切替時は新しい画面の既定へ戻る。既に最新の同一範囲の結果を再利用し、同じ範囲の失敗を自動で無限に再試行しない。
- 自動組版は既存の読取、未保存案合成、実測、世代検証、紙面交換を共用する。正式出力・永続化とは独立。
- 起動時の初期一覧読取完了まで通常操作を無効化し、起動直後のIPC競合を防ぐ。原稿未選択全冊、未保存案、明示範囲、画面再入場のGUI回帰を追加する。
- 全冊の差分組版、読取競合時の再要求、外部リソースの世代管理、厳密なページ位置維持と実機性能は未達。

## スタイル・書籍設定の実測表示（UX-10h-6a）

- 既存 `live-preview-policy.mjs` にデザインの共通スタイルと書籍設定の表示範囲を追加。前者は選択原稿（未選択時は全冊）、後者は全冊。素材・部品ライブラリ・フォント登録画面では共通スタイル紙面の新規自動組版を抑止する。
- 同じ実測エンジン・入力準備・スケジューラ・紙面保持・倍率制御を再利用し、設定用の疑似組版を新設しない。通常画面は設定と紙面を左右、狭い画面は上下に分離する。表示の明示OFFと手動再試行を用意する。
- プレビュー入力には未保存のフォント、用紙、余白、原稿順を含める。保存・復旧トランザクションとは独立し、プレビュー自体は原稿、テーマ、book.yamlを書き換えない。
- 単体検査2件、実際の紙面でフォント・A5幅・余白変更・破棄・保存先ファイル不変を確認するGUI検査を追加。ライブ検査の後はレンダラーを再起動して旧手動検査と分離する。
- 部品Labの登録条件、競合の自動再要求、画像の独立読取、正確な位置復元、実機負荷・レイアウト確認は後続。

## 部品Labの実測と明示登録（UX-10h-7a）

- `lab-measurement-gate.mjs` は実測世代と入力キーを管理する独立モジュール。自動・手動の区別ではなく、現在の作業案と計測入力に一致する成功結果だけが適用・登録・上書きの条件を満たす。
- 見出し・参考書・独自部品および本文段落で共用する。入力変更・再計測・閉鎖で旧結果を失効。フォント、寸法、サンプル等の変更も入力キーで検知する。計測エラー時は登録不可。旧紙面の表示は登録許可を意味しない。
- 適用・新規登録・上書き・共有参照の割当は明示操作のまま。既存の復旧、revision検証、保存側バリデーション、共有参照の影響確認は維持。手動実測は再計測ボタンとして残す。
- 単体検査3件と、自動実測だけでの独自部品登録・段落適用、失敗時の禁止・回復のGUI回帰を追加/更新。Lab内の物理計測の同時実行制限、画像読取分離、部品カタログの実物表示、実機操作は後続。

## 部品カタログ実測・物理計測レーン（UX-10h-7b）

- `measurement-lane.mjs` はレンダラー内で実際の組版計測を1件ずつ実行する共通レーン。執筆/全冊/設定/Labの前景要求を待機中のカタログ要求より優先し、失効した待機要求を省略、実行中の失効結果は採用しない。物理的中断は保証しない。
- `catalog-sample.mjs` はCoreの部品コンパイラを用いて実測用のサンプル入力を生成する。登録部品、標準見出し/本文、教材部品を扱い、文字色だけの疑似見本は使用しない。サンプル番号・文章で計測し、表示は冒頭の一部に限る。
- `catalog-specimen.jsx` は表示範囲近傍だけを計測し、画面や入力キーの変更で旧要求を無効化。カードごとの成功DOMを保持し、幅への縮小は表示専用。失敗時に偽の見本を表示しない。Labや通常操作中の新規要求を抑止する。
- `readPreviewImage` は書籍セッション・送信元・画像IDを検証し、読取専用の画像レーンを利用する。通常操作中または競合後の結果を拒否し、原稿スナップショット読取と画像読取のレーンを分離する。エンジンの既存画像検証とサイズ制限を維持。一般の `readImage` は既存契約のまま。
- 単体検査6件とカタログ検索後の実測DOM検査を追加。画像読取競合時の自動再試行、カタログの永続キャッシュ、処理時間とメモリの計測、実機表示は後続。

## 組版用読取の競合回復（UX-10h-8a）

- `preview-read-retry.mjs` はIPC応答のエラーコードを保持し、`PREVIEW_RETRY` の場合のみ100/200/400/800msの間隔で最大4回再試行する。初回を含め最大5回、待機時間の合計は1.5秒（IPC自体の所要時間を除く）。破損、権限、無効セッション、外部変更などの通常エラーは再試行しない。
- 各試行前・成功後・失敗後に世代を検証し、失効した要求は `PREVIEW_CANCELLED` で打ち切る。古い原稿や書籍の結果は表示しない。原稿の保存・設定保存・登録等の書込には適用しない。
- 原稿スナップショット、実測中の画像、部品Labとカタログの画像に共通利用する。Main側の読取レーンは通常操作の開始によって失効した物理読取の失敗も競合として分類する。
- 上限超過時は既存のエラー表示・手動更新へ戻る。画像再試行の待機中は実測レーンを占有するため、長い前景操作に対する応答性改善は後続。書籍切替時は既存セッション検証も維持する。
- 単体検査7件（回復、上限、永続エラー、取消、IPCコード、実読取レーン連携、失効後の物理失敗）。実GUIでの競合注入・速度とメモリの計測は後続。

## 組版性能の測定基盤（UX-10h-8b）

- `performance-metrics.mjs` はレンダラー内の直近200件の数値記録と集計だけを担当する。対象種別・処理種別・成功/失敗/取消・待機/処理時間・再試行回数のみ許可。原稿、書籍名、ファイルパス、識別子、エラー本文は保存しない。外部送信・永続化なし。
- 共通計測レーンの待機時間と実行時間、選択原稿/全冊の組版要求の待機時間と入力準備からDOM交換までの処理時間、原稿/画像読取の時間・再試行数を別々に記録する。入力合流時間は含まない。組版要求に実測/読取が含まれるので単純加算しない。実行前に組版スケジューラで合流された要求は組版要求集計に入らない。
- `performance-panel.jsx` は明示操作で開き、更新時にスナップショットを集計する。成功時間の中央値・最大値と各結果件数を表示、記録消去が可能。閉じた状態では領域を占有しない。
- Mainの `performanceMemory` は送信元と引数を検証する読取専用IPC。Electronのプロセス作業セットをMain/Renderer/その他に集計し、PIDを返さない。共有メモリの重複を含む概算であり、JSヒープやピーク使用量の測定ではない。
- 数値集計・保存上限・項目制限・待機/実行/取消を単体検査3件で確認し、実GUI回帰で選択原稿/全冊/原稿読取の成功サンプルとメモリ取得・消去を検証。CIログにテスト用書籍の数値ベースラインを出力する。速度合格閾値は固定せず、測定後に決める。
- 大規模書籍の反復ベンチマーク、入力から表示までの体感時間、長時間のメモリ増加、Windows実機の測定・最適化は後続。

## 合成書籍ベンチマーク（UX-10h-8c）

- `benchmark-fixture.mjs` は小6・中10・大20節の3原稿を決定論的に生成し、日英混在本文・インライン数式・例題部品を含む。節内の本文を段階的に長くし、現在の50,000文字/128ブロック/512数式上限内に収める。初回の8/30/75節構成は128ブロック制限を超えたため変更（ベンチマーク報告version 2）。129ブロックの別原稿を用いて超過診断・旧紙面保持・復元を検証する。実書籍・外部素材は使用しない。
- `benchmark-runner.mjs` は一時プロファイルで実GUIを操作する。各原稿の初回表示/再組版、5回の連続入力と最終結果/フォーカス、原稿復元、全冊初回/再組版を検査する。保存済み原稿・manifestは変更されないことを確認する。
- 経過時間は操作開始から最新DOMを25ms間隔で確認するまでの壁時計時間（入力合流・IPC・操作待機・ポーリング誤差を含む）。各終了時点のページ数とプロセス作業セット、内部性能集計を `BENCH report` として出力する。ピークや長時間リークを示す測定ではない。
- `npm run benchmark` は明示的に一時プロファイルを作り、通常の利用者データを使用しない。Linux CIで実行する。Windowsでは終了時に一時プロファイルが残る場合がある。速度閾値はまだ設定しないが、各処理は60秒で打ち切り、紙面失敗・不正な結果を検査する。
- 画像素材の多い負荷、複数回の独立反復、長時間メモリ増加、Windows実機、50,000文字超の大規模組版は後続。

## 大規模組版の設計方針（UX-10h-8d）

- 128ブロックは固定されたエンジンの現行安全制限。Desktopの `validateLayoutOptions` は選択範囲を抽出した後に改ページを含む合計を検査し、計測レーンに入れる前に具体的な診断を返す。エンジン側の制限は緩和しない。
- 大規模組版ではCoreによる全冊の意味解析・参照解決・番号付与を維持したまま、LayoutEngine内の実測、ページ割付、DOM描画の境界を分離する。単純な章ごとの独立ページ結合は禁止（連続開始、左右ページ、番号、明示改ページ、分割可能な段落を壊し得る）。
- 第一段階は実測結果の値データ化と単位テスト、同一入力の互換性検査。第二段階は有界の実測バッチから連続したページ割付状態へ渡す方式。第三段階は計測済みページの必要範囲描画と解放。旧方式とのページ境界・断片・原稿範囲・数式/画像を比較してから、段階的に上限を拡張する。
- 速度の改善量は同一fixture・同一CI環境で比較する。従来のversion 1とは原稿構成が異なるため直接の速度比較はしない。画像・長時間使用・実機での上限は別途検証する。

## 改修の合格条件

各段階で境界ごとの正常・失敗・競合テスト、既存のWindows配布検査、全5CIを確認して統合する。依存の逆流、新規の共有可変状態、無制限の並列実行、暗黙の保存を避ける。大規模一括変更は行わず、小さな変更で旧動作と検証を維持する。性能と実機操作は別途評価する。
