# BookCreator — 設計判断と未決事項

基本設計v0.8.4までの利用者回答を維持する。ここは決定事項の索引と未決の管理先。文法・API・配置の詳細は各正本に従う。

## 決定済み

| ID | 決定 |
| --- | --- |
| Q01 | ファイル境界は既定改ページ、個別変更可 |
| Q02 | 表紙込みPDF、表紙は編集時に本文見開きと独立 |
| Q03 | allow/avoid/strictの3段階 |
| Q04 | インラインと外部Canvasを併用、二重正本なし |
| Q05 | 固定見開きCanvas |
| Q06 | 章節/図表等の自動採番・相互参照、ユーザー設定 |
| Q07 | 数式・脚注・文献引用・構文強調を初期製品目標 |
| Q08 | TypeScript/React/Electron、Win/Linux/macOS、Web移植性 |
| Q09 | HTMLで出版確認、Export時にPDF生成 |
| Q10 | 電子閲覧/両面印刷を分離 |
| Q12 | continuousでは先頭の部品由来開始条件だけ抑制。途中・手動・構造制約は維持 |
| Q13 | 基本機能完成時に開発版公開 |
| A01 | ローカル生成優先、必要な技術は独自実装 |
| A02 | BCMとLayout Engineを独立ライブラリ化。下位ライブラリ同士は必須依存なし |

## 利用者確認が必要

| ID | 内容 | 推奨/状態 |
| --- | --- | --- |
| Q11 | Web正式PDF生成方式 | 既に保留。ブラウザ内優先、無断サーバー送信なし。PoC後 |
| Q14 | 本体・独立ライブラリの最終ライセンス | MITを第一希望。3リポジトリともMITで進めるか、依存確認後に最終確定。未決のためLICENSEは追加しない |
| Q15 | 開発版の公開範囲 | ソース編集・画像・基本組版・HTML/PDFを最小公開ゲートとするか、GUI文章編集・基本部品エディタまで必須とするか。推奨は最初をdeveloper previewとしGUIは次段階で順次公開 |
| Q16 | H1がない原稿・前書き等の番号 | 章番号を見出しからのみ決める方針は既決。上位の番号がない図表/節を単独番号にするか、ファイル単位の章番号を補うか。推奨は存在しない章番号を作らず単独の番号体系を設定可能にする |
| Q17 | 複数ページで同一脚注を参照した場合 | 同じ脚注番号を維持し、参照のある各ページに脚注を再表示するか、最初の参照ページだけに表示するか。推奨は各ページに表示（同一ページでは一回）、脚注が紙面を超える場合は分割/診断を検証 |

Q15〜Q17は提案であり確定していない。既存合意を変更しない。Q16/Q17は該当機能の詳細実装前に必要で、基礎PoCは進められる。Q11/Q14は既に保留のため無理に今決めない。

## 技術的検証後に決める項目

組版器の最終採用・計測精度・内部単位、分割可能なrow/表/脚注、CSS/HTML/PDFの許容差、依存ライブラリと公開名、YAML/BCMの実パーサー、構文競合（ドル記号等）、テーマ継承の細部、Web保存、Git認証/同梱、性能閾値。ユーザーへの影響が大きい場合は確認する。PoC失敗を理由に要件を勝手に削除しない。

## 軽微な整合性修正

- セクション（ファイル/出版順）と章（見出し階層）を区別。
- BCMの共通属性はmargin-topに統一し、captionは自動番号を含まない例に統一。
- プロジェクト形式の番号区間では番号割当と印字有無を別属性にする。
- PagePlanとOutputPagePlanを区別し、UI用の空枠は実ページでないと明記。
- 本体の保存スキーマとEngineの中立スキーマを分離。意味論はEngine、文法はBCMを正本にする。
- 設計上の案と検証済みの実装を区別する。未実装のファイル/コマンドを利用可能と表記しない。
