## 1. 現状分析・成功条件

実画面では左に素材/フォント/部品/書籍設定/原稿一覧、中央に原稿エディタと約30個の書式・参照・部品挿入操作、右に用紙/組版ボタン/フォント役割/テーマ保存/紙面が同時表示される。書籍タイトルと「新規書籍」は見えるが作業工程の切替がない。プレビューの用紙が縦方向に画面を占め、原稿と紙面が別々にスクロールする。利用者がどの対象を選べばどの操作が有効か、局所装飾と共通部品変更の違い、保存と組版の関係を推測する必要がある。これは画面観察であり、操作時間や利用者全員の習熟度の実測ではない。

| 問題 | 設計上の原因 | 解決 |
| --- | --- | --- |
| 何から始めるか分からない | プロジェクト開始と編集コマンドが同列 | ホーム→書籍作成→執筆、状況に応じた次の行動 |
| 操作を探しにくい | 全コマンドを常時並列表示 | 工程・選択・操作頻度の3段階で開示 |
| フォントや部品の効果範囲が不明 | 原稿、テーマ、ローカル表示設定が混在 | 変更対象と反映先を操作前に示す |
| 数式、ID、スロットの難しさ | 内部実装語と作業目的が同列 | 挿入→種類→必要入力→確認。技術属性は詳細 |
| 紙面が占有しすぎる | 分割ビューが固定 | 執筆は広い編集領域、必要時にプレビュー、組版は専用画面 |
| 次の作業と完了状態が不明 | 保存・組版・検査が一つの画面に散在 | 状態表示と次の主操作、出版の確認手順 |
| 編集画面に管理操作が侵入 | ライブラリ管理とインスタンス編集が混在 | デザイン一覧→専用部品編集。フォント/素材管理を別タブ |

### UIの設計原則

1. 一つの画面に一つの主要目的。工程はナビゲーションで、局所操作は選択で見せる。
2. 初回は迷わない既定値。熟練者はショートカット、コマンド検索、詳細設定で同じ機能に速く到達。
3. 「できること」を列挙するのではなく「いま何をすればよいか」を示す。
4. 繰り返し操作は一クリック、稀な操作はメニュー、複雑な変更は専用面、不可逆な変更だけ確認。
5. 作業順は推奨であり強制ウィザードではない。執筆→デザイン→レイアウト→出版からいつでも戻れる。
6. Markdownが正本。表示切替・画面遷移・組版・保存で暗黙の原文書換えをしない。
7. データ保全とアクセシビリティを見た目より優先。機能削除による簡略化は禁止。

## 2. 情報アーキテクチャ

    起動
      └─ ホーム（プロジェクト管理）
          ├─ 新規書籍 → 最小設定 → 執筆
          ├─ 開く → 検証 → 前回画面 / 執筆
          └─ 最近使った書籍（実装後）
      Workspace
          ├─ 執筆 Writing     — 原稿を作る
          ├─ デザイン Design   — 本全体の見た目を定義する
          │   ├─ スタイル（文字・色）
          │   ├─ 部品ライブラリ → 部品エディタ
          │   └─ 素材・フォント管理
          ├─ レイアウト Layout — 実際の紙面を調整する
          ├─ 出版 Publication  — 全体確認・検査・出力
          └─ 書籍設定（全体設定、順序、用紙）
              ソース管理（将来のGit機能、独立画面）

最上位はホーム／執筆／デザイン／レイアウト／出版。書籍設定はプロジェクト名横の設定から開く。素材・フォントはデザイン配下と挿入時のピッカーを共有。Gitは将来の独立機能とし、未実装時は通常のナビに置かない。表紙は設計上Publicationの出版構成から専用エディタへ遷移する。部品の見た目はDesign、原稿の意味内容はWritingへ戻る。

推奨フロー: 新規→執筆→必要なら共通デザイン→全体組版・個別調整→出版検査→出力。デザインの先行作成、部分プレビュー、途中の試し出力は自由。出版の確定だけは既存のゲートを厳守。

画面図は概念ワイヤーフレーム。実装目標値（利用者レビュー後に調整）: 上部タイトル48px、モードバー44px、ステータス28px、左220〜280px、右280〜340px。CSS pxは画面のUIだけに用いる。紙面/テーマの物理寸法はmm/ptを維持。1280×720以上を第一検証対象、1920×1080/Windows 125%・150%も確認。幅不足時は右→左の順で折りたたみ、必要な領域をドロワーとして開く。中央には最大限の幅・高さを割り当てる。パネル幅は利用者が変更でき、最小幅を守る。アプリ全体の縦スクロールを避け、各作業面のスクロールを管理し、固定ヘッダとステータスを維持。スクロール領域の中に同方向のスクロールを無理由に重ねない。

- トップバーは現在の書籍名・保存・プロジェクトメニューのみを基本表示。新規・開くはホームとファイルメニューへ。
- ナビはラベル付き、選択中が明確、アイコン単独にしない。画面下には状態を表示し、操作の羅列にしない。
- パンくず: デザイン > 部品ライブラリ > 例題カード。戻るは書籍や原稿を開き直さない。
- 一画面の主操作は原則1つ（保存、挿入、適用、再組版、検査等の文脈に応じたもの）。共通の保存はヘッダ固定、画面固有の主操作と競合させない。
- 危険操作はメニュー末尾に分離し、色だけでなくラベルで識別。無効の理由をツールチップ・補足文で示す。未実装は基本的に隠し、設計資料に記載。
- パネル折りたたみ、ズーム、前回モード、選択タブはローカルUI設定。book.yamlやテーマを変更しない。個別プロジェクトの原稿位置は再検証して復元する。

## 4. ホーム・書籍設定

### ホーム
アプリ起動時は開いた書籍がなければホーム。中心に「新しい書籍」「既存の書籍を開く」の2択、最近の書籍を下に表示（最近リスト機能実装後）。新規ボタンを主要CTA、既存は副ボタン。サンプル書籍を開く機能は検証済みの教材fixtureを独立した書込み可能なフォルダーに複製する機能として後続追加、原本編集や上書き禁止。空の編集欄や無効な書式ボタンを見せない。

新規作成フォーム: 書名・保存先親フォルダー・フォルダー名（書名から候補、手動変更可）・用紙（A5初期値、A4/JIS B5）を一画面で入力。詳細設定は後から。作成される実パス、既存フォルダーを上書きしないことを示す。「作成して執筆を始める」で既存create APIを呼ぶ。失敗は入力を保持、部分作成フォルダーがあれば表示して利用者が判断。キャンセルはホーム。既存プロジェクトはbook.yamlを開く。読み込み不可なら具体理由と選び直し、勝手に書換えない。

### 書籍設定
専用ページ/広いドロワーで「基本情報」「用紙・余白」「原稿の構成」「出版設定（対応後）」を分ける。A4/A5/JIS B5を物理寸法と簡易用紙図で示し、内側/外側余白、開始面をラベル付きで編集。順序は原稿セクション一覧で移動（現対応範囲）し、章番号・参照が変わる可能性を明示。章の追加/削除/改名はトランザクション実装前には出さない。「変更を保存」と「取消」。用紙を変更すると組版が古くなることを説明。タイトル編集等の未対応項目は設定可能と誤認させない。

## 5. 執筆 Writing

目的: 原稿を完成させる。本文の個別装飾・挿入・修正だけを行う。

    ┌ 執筆 > 第1章                       [GUI | ソース | 分割] [紙面] ┐
    ├────────────┬──────────────────────────────┬──────────────────┤
    │ 原稿          │ 段落 ▾   B I U   リスト ▾  ＋挿入 ▾  … │ 選択した要素         │
    │ ▾ chapter-01  │ 第1章 二次方程式                      │ 種類: 数式            │
    │   はじめに    │ 二次方程式とは…                       │ 数式を編集           │
    │   例題        │ [例題カード]                           │ 番号を付ける □       │
    │               │ x²-5x+6=0                             │ 詳細: ID ▾           │
    └────────────┴──────────────────────────────┴──────────────────┘

- 既定は構造GUI（実装・往復検証済みの要素が揃った時点で切替）。移行初期はソースを既定にし、「ソース編集・GUI準備中」と説明し、機能しないGUIボタンを置かない。ソース・GUI・分割は同じ編集中原稿を参照。紙面は別トグルで必要時に開く。分割表示はソース+GUIまたは編集+紙面の意味を選択ラベルで区別し、初期から3面を固定しない。
- 左は原稿（ファイル）とアウトライン（意味見出し）をタブで区別。選択したファイル/見出しにジャンプ。原稿変更による自動見出し再抽出はIME後。名前の未対応操作は表示しない。
- 通常のツールバーは段落種別、太字、斜体、下線、リスト、挿入、その他の最大7グループを目安。段落種別GUIが未実装なら出さない。幅不足時にラベル付き「その他」へ移す。2段以上の固定リボンにしない。
- 文字を選択した場合に文字書式インスペクタ（色・サイズ・個別フォント・ウェイト・上付き/下付き・継承に戻す）を開く。選択ツールバーは軽量な補助（太字等）、マウスなしでも同じ操作が可能。書式の現在値と混在値、適用範囲、継承元を表示。色を選んだだけで原稿を書換えない。適用の単位は一つのUndo。ソースモードでは既存局所パッチを維持。
- 選択なし: 原稿の編集と挿入。書式が適用不能なら「文字を選択すると使用できます」。数式・参照内部や不明な範囲では無効理由を表示、推測パッチを作らない。
- 挿入メニューはカテゴリ「文章・リスト」「数式・参照」「教材部品」「画像・表等（対応済みのみ）」に整理。通常入力から使う機能だけを上位に。構造GUIはカーソル位置の有効境界へ挿入。現状末尾追加しか安全に実装されていない部品挿入は「原稿末尾に追加」と正確に表記し、カーソル挿入へ移行は局所パッチ試験後。
- 原稿エディタの表示フォントは「表示」メニューへ移動。紙面フォントとは別のローカル設定。「原稿を保存」以外のテーマ保存・用紙設定ボタンを執筆面に置かない。
- 既存紙面選択から原稿範囲を選ぶ機能は保持。部分組版の場合は「この原稿の参考プレビュー」、全冊とは区別。入力時は更新必要を非モーダル表示。自動組版はデバウンス/取消/IME検査後に段階導入、初期は「プレビュー更新」を押す方式でもよい。古い紙面は閲覧専用でクリック編集不可。

### 数式挿入のフロー
挿入→「本文内の数式」または「独立数式」→数式編集ダイアログ/広いインスペクタ→数式入力・描画プレビュー・診断→挿入/更新または取消。独立数式のみ「式番号を付ける」を表示、永続IDは自動生成候補（衝突検査）と詳細編集欄。既存数式選択時だけ編集/採番切替を表示。参照は別の「数式を参照」から式番号・式・原稿名で選択、表示形式を確認して挿入。既存の自動採番/参照制約を維持。無効な数式、対象が移動、古いrevision、参照中の番号解除は理由表示・書換え拒否。取消で原文不変。IME変換中に確定しない。

### 教材部品挿入のフロー
挿入→「教材部品」→例題・問題・解説・ポイント・自作部品等の対応済み一覧（名称・プレビュー・使用目的）→本文と必要スロット→挿入。永続IDと任意スロットは詳細、解説の参照先は対象部品の選択リスト。既存末尾追加では末尾挿入を明示。個別内容は原稿へ、共通デザイン変更は「この部品のデザインを編集」でDesignへ。遷移元の原稿位置を維持し、戻る際はrevision確認。

## 6. デザイン Design

目的: 原稿を触らず本全体の見た目を作る。最初にデザインの一覧を見せ、すべてのプロパティを一度に見せない。

    ┌ デザイン    スタイル | 部品ライブラリ | 素材 | フォント ───────┐
    │ 部品ライブラリ               検索       [＋ 新しい部品]       │
    │ 見出し / 本文 / 教材 / その他    使用中 / すべて               │
    │ [H1 の見本]    [本文の見本]    [例題カードの見本]              │
    │  使用先: H1    使用先: 本文     使用先: 例題                   │
    │  編集          編集             編集                          │
    └──────────────────────────────────────────────────────────────┘

スタイル: 本文・見出し・数式の役割別フォントとウェイトを一つのページに。サンプル、使用中/継承、テーマに反映される範囲を表示。本文色・共通トークンは対応済みのものから。原稿表示フォントはここに混ぜない。テーマ設定の保存と取消を明示。フォント管理へリンク、フォント登録はライセンス・コピー許可・埋込可否を選択時に表示する。Noto Sans JP、STIX Two Mathは同梱と表示。登録済み/使用中/読込失敗を区別。

部品ライブラリ: 既定・自作・使用中・未使用、種別、名前、使用先、共有/独立を表示。「新規」「編集」が中心。割当・複製・名前変更・削除は対象カードのメニューに。削除は使用箇所と参照影響を表示、現在のガードで拒否される場合は理由。既存の独立コピーと共有定義編集を選択前に区別。部品の割当操作と部品の中身の編集を分離し、共有定義変更は影響範囲を確認。未実装の全文使用回数は数を推測せず「使用先確認未対応」。

### 部品エディタ（現Component Labを再構成）

    ┌ デザイン > 部品 > 例題カード     ● 作業案  [破棄] [変更を適用] ┐
    │ [元に戻す] [やり直す]    [＋要素]   [部品 | 紙面 | ストレス]    │
    ├────────────┬─────────────────────────────┬────────────────────┤
    │ レイヤー      │       編集キャンバス                   │ プロパティ           │
    │ ▾ row         │    ┌────────────────────────┐   │ 外観 | 配置 | 詳細 │
    │   矩形         │    │ ■  例題 1.1                 │   │ 選択: 矩形          │
    │   ▾ column    │    │   問題本文                  │   │ 幅 / 高さ / 色      │
    │     ラベル     │    └────────────────────────┘   │ 余白 / 継承          │
    │     本文       │  [サンプルを変更 ▾]   [フィット ▾]    │                    │
    └────────────┴─────────────────────────────┴────────────────────┘

- 左レイヤーツリー: 親子/順序/選択/ロック、複数選択。追加は一つのメニュー（文字、矩形、画像、内容スロット、動的ラベル、グループ）。選択の右クリック/詳細メニューに複製・削除・ロック・グループ化/解除・前後移動を配置。
- 中央: 選択とキャンバスの相互同期、ズーム・フィット、ガイド。スナップ・整列・等間隔は複数選択時だけツールバーに表示。行/列のフローでは順序とgap/幅/整列、CanvasではX/Y/幅/高さ/重なり順を表示し、無効な操作は出さない。ドラッグやリサイズは1ジェスチャ1履歴、キャンセルで原状。
- 右: 選択対象に有効な属性だけを表示。「外観（文字・色・塗り・枠）」「配置（幅・高さ・余白・gap・フロー/Canvas・整列）」「詳細（ID、スロット名・任意性・動的値、改ページ条件等）」、未対応の属性は省略。数値はmm/pt等の単位を隣に表示、制約と継承を示す。複数選択は共通の編集可能属性のみ。
- サンプル編集をキャンバス下の折りたたみパネルに集約。通常は短文、長文・改行・数式・名前付きスロット・任意スロット省略・解説連携などのシナリオを選べる。サンプルは原稿と別の一時状態。複数サンプルを切り替えても部品案は維持。既存共通計測を利用。
- Component / Page / Spread / Stress のうち現在検証済みの表示だけを出す。実原稿の紙面は読取専用で、正式な全体計画か仮配置かを示す。部品単体の成功だけで全冊の成功としない。
- 「変更を適用」は既存の計測成功とrevision/hash前提を満たした時だけ。適用範囲（共有定義なら全対象）を明示。作業案のUndo/Redoは原稿のUndoとは別。適用後に組版失効。適用せずに戻る際は「適用して戻る／破棄して戻る／編集を続ける」。保存で暗黙適用しない。
- 本文フレームのparagraph-labも同じシェルに統合する。ただし実装済みの本文フレーム固有属性（行間・段落間隔・余白等）を出し、未対応のCanvas等を表示しない。

素材: PNG等の対応済み素材一覧、サムネイル・名前・参照情報、インポート。権利確認はインポート時だけ。画像選択ピッカーと共通。クロップは部品/個別画像のプロパティから非破壊編集する。元画像の変更なし。フォント・素材の管理は原稿からリンクしても、完了後元の挿入作業へ戻れる。

## 7. レイアウト Layout

目的: 本全体の紙面を見て、個別の組版を調整する。原稿編集や共通部品編集はリンクで戻る。

    ┌ レイアウト   [全体を組版]   1 / 24ページ   [単ページ ▾] [フィット] ┐
    ├───────────┬──────────────────────────────┬──────────────────────┤
    │ ページ一覧    │          実際の紙面                      │ 選択ブロック           │
    │  1 □          │        ┌─────────────┐          │ 原稿: 第1章            │
    │  2 □          │        │ 第1章           │          │ 位置・適用元           │
    │  3 □          │        │ 本文 …          │          │ 個別の配置（対応時）   │
    │               │        └─────────────┘          │ [原稿へ] [デザインへ]   │
    └───────────┴──────────────────────────────┴──────────────────────┘

既存の全冊/原稿単位組版をここへ。既定は全冊、原稿のみは「簡易確認」。ページ一覧・現在位置・ページ全体フィット・100%・拡大縮小を提供（未実装は段階追加）。用紙の余白ガイドは表示メニューから切替、印刷には含めない。紙面内に操作ボタンを常時重ねない。ページ番号は物理位置と印刷番号を区別し、仮番号なら明示。ページをクリックしたら右に原稿由来、部品由来、分割理由を表示できる範囲で提示。古い組版結果の選択は閲覧のみ。既存Engineの原稿マッピングを利用、再組版で位置を再解決。

後続の個別調整は明示的な操作（次ページから開始、分割制約、サイズ、余白等）から一時案→再組版→適用/取消。自動境界を手動へ無言で固定しない。段落途中の自動分割には有効境界を提示。見開き・手動改ページGUI・個別属性変更は実装と試験後に開放。フロー上の部品を紙面の任意座標へドラッグできるように見せない。対応するCanvas/固定ページだけ自由配置を許す。

## 8. 出版 Publication

目的: 最新の全冊組版を確認してPDF化する。正式出力はまだ開発中。

    │ ページ一覧    │ ガイドなしの確認用紙面                │ 検査結果・出力設定    │
    │              │                                      │ 次に必要な操作        │
    └───────────┴───────────────────────────┴───────────────────┘

各工程の未完了理由を表示。原稿/テーマ/設定の未保存を検出して保存を促す。最新full plan・検査エラーなし・警告確認済み・保存済みsnapshotを確認して正式確定、確定版だけ正式出力。変更で確定解除し旧PDFを消さない。診断から執筆/デザイン/レイアウトの該当箇所へ移動、戻り導線あり。試し出力は正式出力と別のボタンと説明を用意し、最新完全な実験計画からのみ（PE-02実装後）。現在の公開プレビューには保存UIがないため「試しPDF出力」も使用可能とは表示しない。出力UIはM05の既存設計を統合し、署名/正式出版等は実装後に追加。電子/両面・表紙・範囲抽出は対応機能だけを選べるようにする。

## 9. 遷移・保存・状態管理

UIのルート（論理名でありURL実装を強制しない）: Home、Writing(documentId, view)、Design(tab, componentId?, draftId?)、Layout(pageAnchor?)、Publication(step?)、BookSettings(tab)。シェルがworkspaceを保持し、画面切替のmount/unmountで原稿バッファや部品案を消さない。Reactの現在の複数boolean（labOpen/paragraphOpen/studyOpen/creating/showSettings等）を排他的なルート/パネル/ダイアログ状態へ段階置換。既存API/コンポーネントを再利用、main/preloadの権限を拡張しない。

| 操作 | 未保存原稿 | 未適用の部品・設定案 | 組版状態 |
| --- | --- | --- | --- |
| 同一書籍内のモード切替 | 保持。現行単一ファイルバッファで保持できない場合は保存/破棄/取消 | 離れる時に適用/破棄/継続。適用失敗なら移動しない | revisionが同じ場合のみ再利用 |
| 原稿切替 | 現行は保存/破棄/取消。将来は複数バッファ保持を検証後導入 | 必要な場合のみ確認 | 選択原稿プレビューを更新 |
| 共通保存 | 対象を明示して保存（現行は原稿のみ）。保存済み範囲を表示 | 暗黙適用しない | 保存だけでは新しい組版にならない |
| プロジェクト切替/終了 | 保存/破棄/取消。保存失敗時は切替しない | 適用/破棄/継続 | 旧ジョブ取消、旧結果拒否 |
| 外部変更 | バッファ保全、競合表示 | 古い案は再確認 | stale。自動上書き禁止 |
| 出力開始後に編集 | 別revisionとして継続 | 未適用案を出力に混入させない | 元snapshotの出力として区別 |

状態軸: project(open/closed/loading/error)、save(clean/dirty/saving/conflict)、draft(none/editing/invalid/ready/applying)、layout(stale/running/partial/full/failed)、preflight(not-run/running/errors/warnings/ready)、finalization(none/finalized)、export(idle/running/cancelled/failed/succeeded)。一つのenumや単一status文字列にすべて詰め込まない。上部に保存状態、下部に組版状態、出版で検査/確定/出力状態を表示。通知はインラインを優先し、失敗理由と次の操作を添える。編集中の文章をモーダルで遮らない。重大エラーは診断パネルから出所へジャンプ。ログは必要時のみ詳細を開く。遷移・保存・編集・組版・出力コマンドは共通の実行前提・無効理由を持たせ、メニュー/ボタン/ショートカットで違う処理をしない。

選択コンテキスト: documentId, revision, range/nodeKey/persistentId と theme revision, componentId, layerId, draft revision を区別。紙面から遷移しても古いrangeへ書込まない。テーマの作業案と原稿のUndo履歴は分離。単一選択ダイアログ、フォーカス復帰、ESC取消、同時ダイアログ禁止。ユーザーが明示した戻る・閉じる以外の勝手な画面移動をしない。
